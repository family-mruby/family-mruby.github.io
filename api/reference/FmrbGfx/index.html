    FmrbGfx¶

    A canvas: shapes, text, images, sprites

    How to use it: Drawing.

    An app does not make one; it uses the gfx (@gfx) that FmrbApp prepares. The origin (0, 0) is the top-left of the area the app owns, and colours are RGB332 numbers (FmrbGfx::RED and so on). The drawing methods return the canvas itself, so calls chain. Drawing alone shows nothing: call present once at the end of a frame.

    Methods to read first: clear, fill_rect, draw_text, draw_image, present.

    Class methods¶

    FmrbGfx.rgb_to_332¶

    rgb_to_332(Integer r, Integer g, Integer b) -> Integer

    Make a colour from red, green and blue

    Packs three 0-255 values into one byte: three bits of red, three of green, two of blue, so nearby colours collapse onto the same value and fine gradients do not survive.

    Avoid combinations that come out as 0x01. The desktop uses 0x01 as its transparency key, so a window painted with it shows through.

    FmrbGfx.rgb_to_332(255, 0, 0)  #=> 224

    FmrbGfx.video_control¶

    video_control(:play | :pause | :stop | :rewind action) -> video_status?

    Play, pause, stop or rewind the video

    There is one player. Acts on the video video_open opened and returns its state afterwards (nil when there is no answer). :stop closes the file; the canvas keeps the last picture. The wrappers are FmrbVideo's play, pause, stop and rewind.

    FmrbGfx.video_control(:play)

    FmrbGfx.video_status¶

    video_status() -> video_status?

    The video player's state

    {state:, shown:, dropped:}, or nil when there is no answer. state is 0 idle, 1 playing, 2 paused, 3 finished; shown and dropped count frames. The wrapper is FmrbVideo#status.

    st = FmrbGfx.video_status

    FmrbGfx.hsv_to_rgb¶

    hsv_to_rgb(Integer h, Integer s, Integer v) -> Array

    Make a colour from hue, saturation and value

    h is 0-360, s and v are 0-255. It returns [r, g, b], which is not a colour yet -- pass it through rgb_to_332.

    r, g, b = FmrbGfx.hsv_to_rgb(hue, 255, 255)
color = FmrbGfx.rgb_to_332(r, g, b)

    FmrbGfx#origin_x¶

    origin_x() -> Integer

    Where the origin is on the canvas (x)

    Every coordinate drawn is added to it on its way to the canvas (the firmware adds it): 1 for a framed window's gfx, 0 for window_gfx and the rest. While drawing into a sprite image it is not added to what is drawn, but it still is to sprite coordinates (set_sprite_clip, SpriteInstance).

    FmrbApp.set_text_cursor(
  @gfx.origin_x + x,
  @gfx.origin_y + y, 12)

    FmrbGfx#origin_y¶

    origin_y() -> Integer

    Where the origin is on the canvas (y)

    The vertical pair of origin_x: the y of the origin that is added to every coordinate on its way to the canvas. 1 for a framed window's gfx, 0 for window_gfx and the rest.

    FmrbApp.set_text_cursor(
  @gfx.origin_x + x,
  @gfx.origin_y + y, 12)

    FmrbGfx#clear¶

    clear(Integer color) -> FmrbGfx

    Paint the whole canvas one colour

    Fills the whole canvas. In a windowed app that erases the title bar and frame the app drew itself; to clear only the inside of the window use FmrbApp#clear_user_area, which redraws the frame and marks any attached FmrbUI widgets for redraw.

    For a fullscreen app clear is the right call, and faster than a fill_rect over the same area.

    @gfx.clear(FmrbGfx::BLACK)
@gfx.present

    FmrbGfx#get_pixel¶

    get_pixel(Integer x, Integer y) -> Integer

    Read one pixel's colour

    A synchronous round trip to the graphics side. Not something to do per pixel in a loop scanning the screen.

    Outside the canvas it returns 0, which is also black -- the return value does not tell the two apart.

    c = @gfx.get_pixel(60, 40)
# 0 outside the canvas

    draw_thick_line(
  Integer x0,
  Integer y0,
  Integer x1,
  Integer y1,
  Integer thickness,
  Integer color
) -> FmrbGfx

    Draw a line with a thickness

    The graphics side has no thick-line primitive, so this stacks thickness one-pixel lines side by side. The cost grows with the thickness, which shows if thick lines are drawn every frame.

    FmrbGfx#draw_rect¶

    draw_rect(
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  Integer color
) -> FmrbGfx

    Draw the outline of a rectangle

    (x, y) is the top-left corner, w the width, h the height. It draws the outline only, so whatever is underneath stays visible inside. Use fill_rect to colour the inside too.

    gfx.draw_rect(10, 10, 100, 50,
              FmrbGfx::WHITE)  # frame
gfx.fill_rect(12, 12, 96, 46,
              FmrbGfx::BLUE)   # inside
gfx.present

    FmrbGfx#fill_rect¶

    fill_rect(
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  Integer color
) -> FmrbGfx

    Fill a rectangle

    (x, y) is the top-left corner, w the width, h the height, and the inside is filled. To wipe the whole canvas, clear is faster.

    For something that moves, paint over where it was in the background colour first, then draw it at the new place, and it leaves no trail.

    class MyApp < FmrbApp
  def on_update
    # erase the old place
    gfx.fill_rect(@x, 100, 16, 16,
                  FmrbGfx::BLACK)
    @x = @x + 2
    # draw at the new one
    gfx.fill_rect(@x, 100, 16, 16,
                  FmrbGfx::RED)
    gfx.present
  end
end

    FmrbGfx#blend_rect¶

    blend_rect(
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  Integer color,
  Integer mode
) -> FmrbGfx

    Fill a rectangle blended with what is under it

    The last argument is the blend mode -- FmrbGfx::BLEND_ADD or FmrbGfx::BLEND_XOR -- not an opacity. Additive reads as a glow; XOR inverts what is underneath.

    gfx.fill_rect(0, 0, 64, 64, FmrbGfx::BLUE)
gfx.blend_rect(16, 16, 32, 32,
               FmrbGfx::RED, FmrbGfx::BLEND_ADD)

    draw_button(
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  String label,
  Integer fill,
  Integer fg
) -> FmrbGfx

    Draw the picture of a rounded button

    Fills it with fill and centres label in fg with the current font. Only the picture: it has no click target. On a screen redrawn every time, pair it with FmrbUI::HitAreas#add. An eighth argument sets the corner radius (default 3).

    FmrbGfx#picture_info¶

    picture_info(String path) -> picture_info?

    Read a picture file's width and height

    Reads only the head of a PNG or an 8-bit BMP; nothing is decoded (the same C as BMP332.info).     FmrbGfx#draw_picture¶

    draw_picture(String path, Integer x, Integer y) -> bool

    Draw a picture file, reading it in the first time

    Just hand the path (or put_picture's name). A picture is read into a sprite image on the display side the first time; this FmrbGfx keeps up to picture_limit of them (8 unless set), letting the least recently drawn go first. A file written again (another size or time) is read again the next time it is drawn (looked at once a second at most). They all go when the app ends.

    • scale: 1 to 32 turns each pixel into scale x scale; -2 to -32 draws 1/|scale| of the size
    • checker: true lays the checkerboard under the transparent parts (draw_checker)
    • clip: [x, y, w, h] draws only inside that rect

    false when it cannot be drawn (nothing raises); picture_error says why. A picture past 65,536 pixels is refused. A file past 65,536 bytes is read on the app side (BMP332.load: in the VM pool while it is read) and its pixels put. Transparent is the colour 0x01 (a PNG's alpha and tRNS).

    gfx.draw_picture("/home/stamps/a.png",
  10, 20, scale: 2)
gfx.draw_picture(path, 0, 0,
  scale: -2, checker: true)

    FmrbGfx#sync_file¶

    sync_file(String path, ?dest: String) -> bool

    Send an image or sound file across

    The graphics side reads its own filesystem, so an asset has to be put there first. This compares size and CRC32 and transfers only when they differ, so it is fine to call on every start.

    Deciding with file_status[:exists] instead -- "it is there, skip it" -- leaves an edited asset stale for ever. Use this one for assets.

    gfx.sync_file("/home/bird.png",
              dest: "/cache/app/x/bird.png")

    sync_file with nothing left out

    The destination cannot be left out. The wrapper is sync_file (without dest: it uses the same path).

    FmrbGfx#transfer_file¶

    transfer_file(String path) -> bool

    Send a file again whatever happens

    Transfers unconditionally, without looking at what is already there. sync_file is the usual choice; this one is for when the destination is known to need rewriting.

    @gfx.transfer_file("/data/a.bmp")

    FmrbGfx#file_status¶

    file_status(String path) -> file_info

    Whether the file arrived

    Whether the graphics side has the file, and how big it is: {exists:, size:}.

    Do not use it to decide whether to send an asset. exists stays true after the contents change, so an edited asset would stay stale; leave that decision to sync_file.

    st = @gfx.file_status("/data/a.bmp")
st[:exists]
st[:size]
