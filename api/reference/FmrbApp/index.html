    FmrbApp¶

    The base of every app; inherit from it

    How to use it: Application, Inter-App Messaging.

    An app is written as class MyApp < FmrbApp, overriding the methods that get called (on_create, on_update, on_event and so on). The file only defines the class; once it has been read, the class is made and started.

    Draw on gfx (@gfx). @gfx is an FmrbGfx that FmrbApp prepares, with its origin at the top-left of the area the app owns; call gfx.present to show what was drawn. The window's size is read with window_width and window_height, colours with theme_fg and the like.

    Methods to read first: on_create, on_update, on_event, gfx, set_timer, publish.

    FmrbApp.clipboard¶

    clipboard() -> String

    The text on the clipboard

    One clipboard shared by every app; "" when empty. On the PC and in the browser, text copied there too. Given a number, at most that many bytes, never cutting a character.

    text = FmrbApp.clipboard

    FmrbApp.clipboard_raw¶

    clipboard_raw(Integer limit) -> String

    clipboard with nothing left out

    The simple form, with no argument left out. limit 0 gives all of it; above 0, at most that many bytes, never cutting a character. The wrapper is clipboard (limit left out is 0).

    text = FmrbApp.clipboard_raw(0)

    FmrbApp.notify¶

    notify(String summary, String body) -> bool

    Show a small notice at the top right

    It goes after a few seconds: the app's name, the text and the body (two lines at most). Only the PC shows them; elsewhere nothing shows and the answer is false.

    FmrbApp.notify("Saved", "/home/a.txt")

    FmrbApp.checkpoint¶

    checkpoint(Integer pid) -> String?

    Write another app to an image

    Asks for app pid to be stopped, written to an image and closed (the shell's checkpoint); restart: true starts it again at once. nil when asked, else a String saying why not. The answer arrives later at on_control as {"cmd" => "checkpoint_result", "pid", "ok", "path" or "reason"}.

    FmrbApp.checkpoint(5,
                   restart: true)

    FmrbApp.move¶

    move(Integer pid, String to) -> String?

    Move another app to another machine

    Asks for app pid to be moved to the Asterism machine to (its node ID; the shell's move). nil when asked, else a String saying why not. The answer arrives later at on_control as {"cmd" => "checkpoint_result", "pid", "ok", "to", "there" and "missing" or "reason"}.

    FmrbApp.move(5, "fmruby-abcdef")

    FmrbApp.last_error¶

    last_error() -> Hash?

    The error of the app that failed last

    The name and the error text of the last app that failed, as a Hash {name:, error:}. It is filled when a Ruby app ends on an exception, does not compile, is refused at start or cannot be restored from an image, and when a second Python app is started. There is one for all apps: the next app that fails replaces it. It is never cleared, and is nil until some app has failed since boot. name is the app's name (up to 31 bytes); error is the exception's text followed by the backtrace, one line each, if there is one (1023 bytes in all at most). Tell whether it is your own by name.

    e = FmrbApp.last_error
Log.info("#{e[:name]}: #{e[:error]}") if e

    FmrbApp.pool_used¶

    pool_used() -> Integer

    How much of its own memory is used, in bytes

    -1 when it cannot be read. Use it where the percent is too coarse: one percent of the desktop's 1536KB pool is 15KB. Subtract across a piece of work and you have the garbage it made.

    before = FmrbApp.pool_used
scan_everything
kb = (FmrbApp.pool_used - before) / 1024

    FmrbApp.wasm_stats¶

    wasm_stats() -> wasm_stats

    How the wasm runtime is doing

    The runtime wasm apps run on (WAMR). running is 1 while it is up (while any wasm app runs), apps the apps using it, modules the modules loaded, natives the boundary's functions the firmware gives. pool_* is the shared pool every wasm app takes from (bytes; high is the most since boot), traps the calls that trapped (or ran too long) since boot. All 0 on a machine without wasm apps (the ESP32-S3).

    w = FmrbApp.wasm_stats
Log.info("#{w[:pool_used]} of #{w[:pool_total]}") if w[:running] == 1

    FmrbApp.wasm_app_stats¶

    wasm_app_stats(Integer pid) -> wasm_app_stats?

    How one wasm app is doing

    The wasm app pid, or nil when pid is not one. pages is its linear memory now and max_pages the most it may grow to (64 KB pages), binary_size its .wasm, hook_us how long the last hook call (on_update and the others) took and hook_max_us the longest (microseconds), calls the hook calls so far.

    s = FmrbApp.wasm_app_stats(pid)
Log.info("#{s[:pages]}/#{s[:max_pages]} pages") if s

    FmrbApp.set_kana_mode¶

    set_kana_mode(Integer mode) -> void

    FmrbApp#on_restore¶

    on_restore() -> void

    Called when started from an image

    Called in an app started from an image, just before it goes on from where it was written. Its instance variables, Tasks and timers are back as they were. The base has made its window again (the same place, size and frame, its fonts and GfxBlocks) and subscribed to its topics again, and the keyboard comes to it. What was drawn does not come back: the window is an empty frame, so an app that draws only when something happens draws here (one that draws everything in on_update need not). Make again here what the app itself made outside the VM (sprites, images). An app holding a file open cannot be written to an image. Moved to a machine with another screen (Retro and Modern), the window may be made smaller to fit it, or a fullscreen app gets that screen's size: on_resize then comes before on_restore, as after a resize. The build it moved to may lack a method not common to every machine: check with respond_to? or rescue NoMethodError (gather the differences in a small object of the app's own and absorb them there with respond_to? or method_missing; adding method_missing to a built-in class such as Array is not recommended). The arriving side tells the names it lacks in its log and its answer, and does not refuse. A method the app cannot go on without goes in its .app.toml as requires = ["name"]: it is not moved to a build without it. See doc/checkpoint/movable_apps.md.

    def on_restore
  draw_screen
end

    FmrbApp#on_event¶

    on_event(event ev) -> void

    called on key and mouse input

    ev is a Hash describing the input. Four fields cover most uses:

    • ev[:type] -- what happened: :key_down, :mouse_up and so on
    • ev[:scancode] -- the key's number. Look at this, not the character (kana input delivers the same numbers)
    • ev[:x] ev[:y] -- where the mouse is (from the area's top-left, as gfx draws; from the window's: ev[:wx] ev[:wy])

    Use ev_ctrl?(ev) and friends to see whether Ctrl or Shift was held.

    class MyApp < FmrbApp
  def on_event(ev)
    return unless
      ev[:type] == :key_down
    case ev[:scancode]
    when 0x4F then @x += 4  # right
    when 0x50 then @x -= 4  # left
    end
  end
end

    Rewrite keys in the settings file

    values is a Hash of key => value. Only the lines of the keys given are rewritten and the rest stay as they are (the file is made when it is missing). A key is "city" or "section.key", and a nil value removes it.

    It returns the Hash read back after writing, and nil when it could not write, the read-back differs, or the file is not TOML (the file is not touched then; FmrbToml.error says why).

    save_app_settings({ "city" => name })

    FmrbApp#app_state¶

    app_state(?String who) -> Hash[String, untyped]

    Read what the app remembered (lost on restart)

    Returns /tmp/<who>.state.toml as a Hash with String keys. It is gone after a restart (power on a device, the program on a PC, the page in a browser), so the user's settings belong in app_settings. Only strings, integers and true/false are kept. who (app_handle_name when left out) is for a part of a program that keeps its own state. {} when the file is missing or not TOML.

    dir = app_state("file_manager")["dir"]

    FmrbApp#set_timer¶

    set_timer(Integer interval) -> Integer

    Ask to be called on a timer

    Calls the block once, interval milliseconds later. It does not repeat -- call set_timer again inside the block for that.

    The moment it fires is rounded to the app loop's own tick, so it is not accurate to the millisecond. The return value is the id clear_timer takes.

    Under Spinel a stored block cannot capture an outer local variable (instance variables and constants are fine).

    @id = set_timer(500) { blink }

    FmrbApp#publish¶

    publish(String topic, ?untyped data) -> void

    Send a notice to everyone

    Sends data to every app subscribed to that topic.

    One message carries at most 176 bytes. For anything larger, write it to /tmp and publish the path instead (/tmp lives in memory and is gone on the next boot).

    publish("my_topic", { "n" => 1 })

    FmrbApp#send_message¶

    send_message(Integer dest_pid, Integer msg_type, untyped data) -> bool

    Send a message to another app

    Sends straight to one process (dest_pid). data is any value MessagePack can pack (usually a Hash), and the packed size may be 176 bytes at most, the same limit as publish. msg_type is FmrbConst::MSG_TYPE_APP_CONTROL.

    It returns true when sent, and false when the target has no queue (wrong pid, already ended) or does not take it within one second (also logged). Over 176 bytes raises ArgumentError. The sender's pid is not put in the message; add it yourself when you want a reply ("re" => FmrbApp.pid).

    The receiver reads only a Hash whose "cmd" is a String. The cmd names the base owns (resize, moved, suspend, resume, stop, quit_request, ...) are handled by the base, and any other cmd reaches on_control as the Hash (if defined). A Hash without "cmd", or anything that is not a Hash, is dropped silently.

    send_message(pid,
  FmrbConst::MSG_TYPE_APP_CONTROL,
  { "cmd" => "hello",
    "re" => FmrbApp.pid })

    FmrbApp#checkpoint¶

    checkpoint() -> String?

    Write this app to an image and close

    Asks for this app to be stopped, written to an image (/tmp/<name>.ckpt) and closed. The image is written at the break after the message wait, so asking from on_event or on_update is fine. Once written the app closes after on_checkpoint; given restart: true the image is started again at once (on_restore). A refusal arrives as on_checkpoint_refused. nil when asked, else a String saying why not.

    why = checkpoint(restart: true)
Log.warn(why) if why

    FmrbApp#move_to¶

    move_to(String to) -> String?

    Move this app to another machine

    Asks for this app to be moved to the Asterism machine to (its node ID). The kernel asks that machine first whether it has the methods the app calls, writes the image, carries it and closes the app here once it is up there (on_checkpoint last here, on_restore there). When it stays (refused, no answer), on_checkpoint_refused says why and the app goes on. nil when asked, else a String saying why not.

    why = move_to("fmruby-abcdef")
Log.warn(why) if why

    FmrbApp#idle_gc=¶

    idle_gc=(bool enable) -> void

    Collect garbage while idle

    Set true in an app that has to keep a rhythm (playing a song, animating). Collection runs in small steps while the app waits, so the stops of 100 ms or more in the middle of a phrase become rare. The generational mode goes off and does not come back, and a message waits until the running step ends. Where it is unavailable it logs and leaves everything as it was, with idle_gc still false.

    def on_create
  self.idle_gc = true
end
