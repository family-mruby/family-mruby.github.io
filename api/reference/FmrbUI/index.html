    FmrbUI¶

    Widget container

    How to use it: UI Widgets.

    Class methods¶

    FmrbUI.new¶

    new(
  FmrbApp app,
  ?bg: Integer,
  ?text_size: Integer,
  ?bg_painter: untyped
) -> FmrbUI

    Create the widget box

    Pass the app itself (FmrbApp). The canvas and the user-area origin are read from it.

    bg: is the colour a widget paints inside itself - a Label's box, a Stepper's value field, a Scrollbar's track. It defaults to the window background; an app that clears its user area to something darker passes that colour instead. Left out, it becomes the window background of the machine an app is moved to (a colour passed is kept).

    bg_painter: is who repaints the ground where a widget used to be. Left out, the hole is filled with bg:, which is right while the ground is one colour. Where it is a picture - wallpaper, a border, a rounded corner - pass an object answering paint_bg_rect(gfx, x, y, w, h), usually self. That method draws the rectangle and nothing else: no present, no allocation, and it puts back any text size or font it changed. The name is fixed.

    text_size: is the default scale for the widgets made from here on (1 unless given). A single widget can override it with its own text_size:. The size is fixed when the widget is made and never follows the size the app happens to be in, and flush hands the app's size back afterwards.

    FmrbUI#label¶

    label(
  Symbol id,
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  String text,
  ?align: Symbol,
  ?text_size: Integer

    Place a text label

    align: chooses the alignment (:left / :center / :right, default :left). text_size: enlarges this one widget's text (1-4); useful for a heading.

    @ui.label(:l_size, 4, 148, 60, 10,
          "Size")

    FmrbUI#button¶

    button(
  Symbol id,
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  String text,
  ?text_size: Integer,
  ?accent: Integer
) -> FmrbUI::Button

    Place a push button

    Inverted while held; handle returns the id when the button is released on top of it. Releasing outside does nothing. text_size: enlarges the label (1-4), as on every widget.

    accent: paints the button in that RGB332 colour instead of the theme's. Reserve it for the few controls whose colour carries meaning - a confirm dialog's Yes, a transport's Stop. On a Toggle it is the on colour.

    @ui.button(:start, 4, 20, 60, 16,
           "Start")

    FmrbUI#toggle¶

    toggle(
  Symbol id,

  Integer y,

  Integer h,
  String text,
  ?group: Symbol,
  ?on: bool,
  ?on_text: String,
  ?text_size: Integer,

    Place an on/off toggle

    Toggles sharing a group: name behave as radio buttons - only one is on. on: true starts it on; on_text: gives it a different label when on.

    FmrbUI#stepper¶

    stepper(
  Symbol id,
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  Integer value,
  Integer min,
  Integer max,
  ?Integer step,
  ?text_size: Integer
) -> FmrbUI::Stepper

    Place a value stepper

    A "< value >" control. handle returns the id for either side, the value stops at min / max, and pressing at the end returns nothing. An optional last argument sets the step (default 1).

    FmrbUI#enum¶

    enum(
  Symbol id,
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  Array[String] options,
  ?index: Integer,
  ?text_size: Integer
) -> FmrbUI::Enum

    Place a choice picker

    A "< choice >" control over options. value is the chosen index and option_text the string. It stops at the ends rather than wrapping, and builds no string when moved, which makes it lighter than a Stepper. index: (0 when left out) is the choice shown first, text_size: the text scale of this widget alone. options is read, never written.

    FmrbUI#scrollbar¶

    scrollbar(
  Symbol id,
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  Integer total,
  Integer visible,
  ?Integer scroll
) -> FmrbUI::Scrollbar

    Place a vertical scrollbar

    x, y, w, h are the bar itself, not the list it scrolls (10 wide is the usual). total (how many there are), visible (how many fit) and scroll (the position; 0 when left out) are all it needs. The app owns the position. Push it in with set_value when keys move it, call set_range when the count changes, and read it back with value after the bar is pressed. The wheel is not answered here (use wheel_rows).

    handle returns the id on the press (not the release), once for a held press. One press moves one step, and a press at an end returns nothing. direction says which way a held bar goes; the app does the repeating. While everything fits (total at most visible) it draws nothing and clicks pass through to the list behind. It is meant to be made in on_create (making allocates; an app whose window resizes builds it again in on_resize).

    @ui.scrollbar(:sb, w - 10, y, 10, h,
              0, rows, 0)
# ...
@ui.set_range(:sb, @files.size, rows)
@ui.set_value(:sb, @scroll)

    FmrbUI#option_text¶

    option_text(Symbol id) -> String?

    The chosen string

    What the Enum is showing. Its index is read with value.

    name = @ui.option_text(:mode)

    FmrbUI#text_field¶

    text_field(
  Symbol id,
  Integer x,
  Integer y,
  Integer w,
  Integer h,
  ?String text,
  ?max: Integer,
  ?text_size: Integer
) -> FmrbUI::TextField

    Place a one-line text field

    Click to focus; keys go to whichever field has the focus. Enter makes handle report the id, Escape drops the focus. The caret does not blink (blinking would mean drawing every frame) and there are no arrow keys: characters go on the end and backspace takes from the end.

    FmrbUI#handle¶

    handle(Hash[Symbol, untyped] ev) -> Symbol?

    Feed one event

    Returns the id of the widget whose operation completed, or nil. A press only updates the pressed look and returns nil; the id comes when the button is released over the same widget. mouse_move does nothing.

    case @ui.handle(ev)
when :start then start_game
end

    FmrbUI#flush¶

    flush() -> bool

    Draw the changed widgets

    Calls present once when anything was drawn and returns true; returns false without drawing when nothing changed. Call it after drawing your own picture so present happens only once.

    draw_picture
@gfx.present unless @ui.flush

    FmrbUI#set_range¶

    set_range(Symbol id, Integer min, Integer max) -> void

    Change a widget's range

    The two numbers mean different things. A Stepper (and Enum) takes (min, max), a Scrollbar (total, visible). The value is pulled inside the new range. The same range does nothing, an unknown id does nothing (it always returns nil), and other widgets ignore it.

    @ui.set_range(:track, 1, total)    # Stepper
@ui.set_range(:sb, @files.size, 8) # Scrollbar

    FmrbUI#direction¶

    direction(Symbol id) -> Integer

    Which way a scrollbar is held

    -1 while held up, 1 held down, 0 when not held (and for an unknown id). Read it after handle returns the id to drive the repeat.

    if @ui.handle(ev) == :sb
  d = @ui.direction(:sb)
  @scroll_hold = d
end

    FmrbUI#bg=¶

    bg=(Integer c) -> void

    Change the colour behind the widgets

    Changes what widgets made afterwards, and the hole left by a hidden one, are painted with, and the widgets that already exist too: each one whose colour was copied from here when it was made takes the new one and is redrawn at the next flush. A widget given its own colour with its bg= keeps it. The colour counts as the app's own and does not turn back into the theme's after a move to another machine. The ground outside the widgets is the app's to repaint.

    @ui.bg = @bg_col
@ui.flush
