    Linux 版¶

    Family mruby は、Linux のパソコンで 1 つのプログラムとしても動きます。中身は実機と 同じシステム (デスクトップ、エディタ、Shell、標準アプリ、Ruby の API) で、Modern の画面を ディスプレイに合わせて拡大して表示します。ログイン画面で選ぶとそれがデスクトップになり、 パソコンのアプリ (端末やブラウザ) も Family mruby のウィンドウとして並びます。

    (開発版) と書いた項目は開発ブランチにだけあり、3.0.0 とそのパッケージにはまだ 入っていません。次のリリースで入ります。

    インストール¶

    パッケージは .deb で、GitHub の各リリース に添付しています。

    パッケージ 対象 状況
    amd64 Ubuntu 26.04 以降 のパソコン (または同じ wlroots 0.19 を持つディストリビューション) 3.0.0 に添付
    arm64 M5Stack の APPLaunch ランチャーを使う arm64 の小型 Linux 機 (Cardputer Zero)。本体の画面用と HDMI 用の 2 つの項目が入ります (開発版)。ビルドはできていますが、その実機ではまだ確認していません

    apt で入れると、必要なライブラリも一緒に入ります。

    sudo apt install ./family-mruby_<version>_amd64.deb

    apt は推奨パッケージもいくつか提案します。どれも任意で、無ければその機能が使えないだけです。

    パッケージ 加わる機能
    xwayland X11 のアプリ (Wayland のアプリは無くても動きます)
    swaylock 電源メニューの ロック、休止やふたを閉じたときの画面ロック
    xdg-desktop-portal-wlr ブラウザのビデオ会議からの画面共有・録画
    fcitx5、fcitx5-mozc (提案) Linux のアプリと Family mruby のアプリの両方で、かな漢字変換。無ければ Family mruby 自身のかな入力を使います

    入るものと動き方¶

    パス 内容
    /usr/bin/family-mruby プログラム本体
    /usr/bin/family-mruby-session ログイン画面のセッション。プログラムを起動し、見守ります
    /usr/share/wayland-sessions/family-mruby.desktop ログイン画面の Family mruby の項目
    /usr/share/family-mruby/root/ システムのファイル (/app、/usr、出荷時の /etc、機種の定義)。読み出し専用

    ログイン画面のセッションでは、プログラムが 自分で Wayland のコンポジタ になります。 画面・キーボード・タッチパッド・マウスを自分で扱い、Family mruby の画面を整数倍に拡大して 敷き、その上に Linux のアプリのウィンドウをディスプレイ本来の解像度で重ねます。Linux の ウィンドウにも Family mruby のタイトルバー・枠・閉じるボタンが付き、ほかのウィンドウと 同じように重なり・移動・リサイズします。Family mruby の音は PipeWire か PulseAudio に出ます。

    プログラムが異常終了すると、セッションが起動し直して通知で知らせます。1 分以内に 4 回 落ちると諦めて、ログイン画面に戻ります。セッション自身のログは ~/.local/state/family-mruby/session.log です。

    初めての起動¶

    1. ログアウトします。ログイン画面のセッションの選択 (ディスプレイマネージャのメニュー) で Family mruby を選んでログインします。
    2. Family mruby のデスクトップが英語で起動します。言語・タイムゾーンなどは、実機と同じく システムメニューの Config で変えます。
    3. キーボードの配列は Linux の設定に合わせます (keyboard_layout = "auto")。

    いつものデスクトップのまま試すなら、端末から起動します。

    family-mruby                         # ウィンドウで (機種の定義 sdl)
family-mruby --machine linux_pc_wl   # 今のデスクトップの中に、入れ子のコンポジタとして

    機種の定義¶

    どの画面・入力・音を使うか、画面の大きさ、デスクトップの種類は、機種の定義 という 小さな TOML ファイルで決めます。パッケージに入っている定義は /usr/share/family-mruby/root/machines/ にあります。

    名前 内容
    sdl 既存のデスクトップの上のウィンドウ。--machine を付けないときの既定
    linux_pc_wl プログラムが Wayland のコンポジタになる形。ログイン画面のセッションが使います
    linux_pc 以前のセッションの形。コンポジタ cage の中の全画面のウィンドウ 1 つ
    linux_pc_drm テキストのコンソールから、コンポジタなしでディスプレイ (DRM/KMS) に直接出す形
    cardputer_zero、cardputer_zero_hdmi arm64 のパッケージの 2 つの起動項目 (本体の 320x170 の画面とキーボード専用のデスクトップ、HDMI)

    --machine には名前か、自分で書いたファイルのパスを渡します。--set key=value で 1 項目 だけ変えられます (--set display.rotate=90)。定義に書いた画面・入力・音が開けないときは、 別のものに黙って切り替えず、理由を出して終了します (終了コード 3)。

    設定¶

    ログイン画面のセッション¶

    セッションは /etc/default/family-mruby-session (シェルの断片。無ければ root で作ります) を 読みます。

    ROTATE=90                     # 0、90、180、270: 横向きに付いたディスプレイを回す
FMRB_ARGS="--set display.look=crt"   # プログラムに渡す引数

    仮想マシンの中では、セッションが GPU を使わない描画 (WLR_RENDERER=pixman) とソフトウェア 描画のマウスポインタに切り替えます。仮想マシンの表示アダプタでは、コンポジタが使える GPU が まず得られないためです。ファイルに WLR_RENDERER=gles2 と書けば GPU を試せます。

    CRT 風の表示 (開発版)¶

    Linux のウィンドウも含めた画面全体を、ブラウン管 (CRT) 風に描けます。走査線・シャドウマスク・ にじみ・画面の湾曲・周辺減光に加え、NTSC の色にじみ・ちらつき・ノイズがあります。GPU が 必要です。システムメニューの 画面... を開き、「くっきり」と「ブラウン管」の切り替え、効果ごとの 強さ (0〜100)、ひと揃いの値を入れる 標準・強め のボタンが使えます。変更はすぐ効き、 /etc/system_conf.toml の [crt] に保存され、FMRB_ARGS の指定より優先されます。

    電源メニュー¶

    メニューバーの右端のボタンに、パソコンでできる操作が入っています。どれも実行の前に 確認します。

    項目 内容
    ロック 画面をロックします (swaylock が必要。Linux のパスワードを聞かれます)
    休止 パソコンを休止します
    ログアウト セッションを終えてログイン画面に戻ります。中で起動した Linux のアプリには先に終了をリクエストし、数秒たっても残っていれば終了させます。この名前は (開発版) で、3.0.0 では同じ項目を 終了 と呼んでいます
    再起動 パソコンを再起動します
    電源を切る パソコンの電源を切ります

    sdl のウィンドウでは 終了 だけで、プログラムを終えます。

    ランチャーの Linux のアプリ¶

    ランチャーに Linux の区分 (ペンギンのアイコン) があり、パソコンに入っているアプリが 並びます。/usr/share/applications と ~/.local/share/applications の .desktop ファイルに 書かれたものです。区分を開いてアプリをダブルクリックすると起動し、.. で戻ります。 Family mruby のアプリと同じく、右クリックのメニューでデスクトップに置けます。X11 のアプリは、 最初の 1 つを開いたときに Xwayland を起動します。

    パソコンでのウィンドウの操作です。

    キー・操作 働き
    タイトルバーをダブルクリック 最大化、または元に戻す
    Super + 矢印 ウィンドウを並べる: 左右で半分、上で最大化、下で元に戻す
    Ctrl + Tab、Ctrl + , Linux のウィンドウがキーボードを持っていても、常に Family mruby に届く

    ファイルを Linux のアプリで開く¶

    File Manager は、Family mruby が開ける種類のファイルを今までどおり開き、それ以外の種類は Linux でその種類の既定のアプリに渡します。ファイルを右クリックすると Linux のアプリで開く があり、その種類を開けるアプリが並びます。ファイルの関連付け の表でも、Linux のアプリを行き先に書けます。

    Shell から Linux のコマンド¶

    ! で始まる行は Linux のコマンドとして、Shell の今のディレクトリに対応する Linux の ディレクトリで実行します (/mnt/host/src なら ~/src)。

    > !git status
> !ls -l
> !

    ! だけなら Shell の中で Linux のシェル (bash、無ければ sh) に入り、exit か Ctrl + D で戻ります。Ctrl + C で実行中のコマンドを止め、Ctrl + Shift + V で実行中の コマンドに貼り付けます。出力の色は表示しますが、vim や top のような全画面のプログラムには 対応していません。Shell のコマンド も参照してください。

    ファイルの置き場所¶

    Family mruby からは実機と同じ 1 つのファイルシステムに見えますが、最上位の場所ごとに パソコンの別の場所に置かれます。

    Family mruby の中 パソコンの上
    /home、/etc、/app/usr ~/.local/share/family-mruby/ (home/、etc/、app/usr/)。あなたのもので、更新しても残ります
    /tmp、/var、/cache、/data ~/.cache/family-mruby/。消しても作り直されます
    /app、/usr、/lib、/help など /usr/share/family-mruby/root/。読み出し専用で、パッケージの更新で入れ替わります
    /mnt/host Linux のホームディレクトリ (読み書き)
    /mnt/root Linux の / (読み出しのみ)

    /etc は初回の起動でシステムのものから写します。更新の後は、パッケージで新しく増えた 設定の項目だけを足し、あなたが設定した値は変えません。実機と違い、新しいリリースを入れても /home は消えません。新しい .deb を入れてもそのまま残ります。

    Wi-Fi・Bluetooth・音量・通知¶

    NetworkManager と BlueZ が動いていれば (普通の Ubuntu のデスクトップなら動いています)、 Family mruby の設定ウィンドウから操作できます。

    • Wi-Fi: ネットワークのダイアログの Wi-Fi... から開きます。届いているネットワークの 一覧、接続と切断。パスワードは NetworkManager に渡し、NetworkManager が自分のツールで 設定したときと同じように保存します。
    • Bluetooth: システムメニューから開きます。アダプタのオン・オフ、ペアリング済みの機器の 接続と切断。新しい機器のペアリングは Linux 側のツールで行います。
    • 音量: メニューバーのスピーカーと Config の音量が、パソコンの出力の音量 (PipeWire か PulseAudio) を動かします。音量キーも効きます。
    • Linux のアプリの 通知 は右上に出ます。

    NetworkManager や BlueZ が無いときも、ネットワークの状態は表示し、それぞれのページは 出ません。

    Asterism¶

    パッケージにはルータが設定されていません。実機と同じく /home/asterism/config.toml に ルータを書いてください (ネットワーク を参照)。 TLS のルータ (tls/...) と、コンソールで作った認証情報の .tar もパソコンから使えます (開発版)。

    タッチパッドとタッチパネル (開発版)¶

    コンポジタのセッションでは、タッチパッドのタップでクリックし (1 本指で左、2 本指で右。 タップして動かすとドラッグ)、2 本指のスクロールはホイールの 1 目盛りずつ進みます。タッチ パネルは触った所でクリック・ドラッグし、ROTATE の回転にも合わせます。3.0.0 では タッチパッドは押し込まないとクリックにならず、タッチパネルは使えません。

    制約¶

    • 画面: Family mruby の画面はディスプレイの解像度の半分です (1280x800 なら 640x400)。 縦長や小さいディスプレイでは 426x240 になります。拡大は整数倍だけで、余りは黒です。全画面の アプリは Modern の 426x240 (高解像度のアプリは 640x360) を、入る最大の整数倍で表示します。 ディスプレイは 1 台だけです。
    • Linux のウィンドウ は全画面にはなりません。最大化が一番大きい状態です。
    • Shell の ! は行の出力と色だけを扱います (TERM=dumb)。
    • SD カードはありません。/mnt/sd と /sd は無いので、/mnt/host を使ってください。
    • ハードウェアのピンはありません。GPIO・I2C・GROVE・実機のセンサは使えません。
    • Retro (2 チップ構成) の Linux 版はありません。シミュレータ を使ってください。
    • セキュリティ: Family mruby のどのアプリも、Linux のプログラムの起動、Linux のコマンドの 実行、/mnt/host を通したホームディレクトリの読み書きができます (Linux のユーザの権限で)。 セッションの中のどの Wayland のアプリも、X11 と同じく画面を取り込んだり、フォーカスのある ウィンドウに打鍵を送ったりできます。リモートデバッガはパッケージでは止めてあり、有効に したとき (/etc/system_conf.toml の debugd = true) も 127.0.0.1 だけで待ち受けます。 制約事項 も参照してください。
